---
name: inspect-mps-project
description: Inspects project modules, model roots and dependency boundaries through semantic tooling.
---

After context/provider discovery, navigate the intended open project and bounded
module/model/root trees. Separate editable models from language implementations,
generators, runtimes, build modules, examples/tests and generated output.
Do not manually inspect or modify serialized `.mps`, `.mpl` or module persistence.

For migration diagnostics, inspect semantic ancestry before classifying unresolved
references as active behavior. Comment attributes can retain obsolete references
that migration checks still visit. Inspect that dependency closure before any
authorized removal; compare active trees and preserve live identities. Never
retarget deleted declarations by name or delete active roots to silence checks.

Inspect deployed metamodel specialization when a containment role changes across
releases. A specialized link can expose a different canonical containment role;
verify the exact release APIs and preserve child identity and value.
For missing structure descriptor generation, inspect semantic devkit imports and
generation-plan checkpoints instead of weakening reference generation.

Loading success is distinct from mutation freshness and compilation success.
If access fails, retain the diagnostic rather than starting a broad rebuild.
Follow `.agents/SELF_LEARNING.md` for public reusable findings.
